# 三、产品技术实现路线

## 3.1 总体架构

平台采用四层解耦架构，自上而下分别为交互呈现层、业务服务层、智能算法层与数据存储层。

| 层次 | 技术选型 | 职责 |
|---|---|---|
| 交互呈现层 | Vue 3 + TypeScript + Vite + Element Plus + ECharts 5 + Pinia | 7 个业务组件：企业列表、企业画像、里程碑看板、专利网络图、团队画像、授信模拟器、风控预警；响应式断点 1024px / 640px |
| 业务服务层 | FastAPI + SQLAlchemy 2 + Pydantic | 13 个 REST 端点，覆盖企业、估值、团队、专利、里程碑、授信、风控全链路；异步推理编排 |
| 智能算法层 | XGBoost 2.0 + scikit-learn 1.5 + NetworkX 3.2 | 估值回归模型、破产风险分类模型、PageRank 专利网络；模型异常时回退规则公式 |
| 数据存储层 | SQLite（开发）/ MySQL（生产）+ Redis（可选，降级不影响主流程） | 企业档案、模型产物、里程碑状态、推理日志 |

四层之间通过明确定义的接口契约通信，任一层的实现替换不影响其他层，便于在银行现有技术栈中做增量集成。

## 3.2 算法实现

### 3.2.1 估值模型（Regressor）

- **任务**：预测企业基础估值与当前估值两个目标
- **数据**：2000 条硬科技企业数据，8 个输入特征（含行业与阶段类别变量）
- **预处理**：类别特征 OneHot 编码，数值特征直通
- **模型配置**：XGBoost，300 棵树，max_depth=6
- **特征工程**：引入非线性与交互项 patent_count^0.7、team_score^1.5、log(员工数)、√(质量 × 团队评分)
- **效果**：基础估值 R² = 0.927，当前估值 R² = 0.954

### 3.2.2 风险模型（Classifier）

- **任务**：预测企业破产风险
- **数据**：真实企业财务公开数据集 6819 条 × 95 个财务特征；未破产 6599 条 vs 破产 220 条（破产率 3.23%）
- **不平衡处理**：scale_pos_weight = 30
- **模型配置**：XGBoost，300 棵树，max_depth=5
- **效果**：AUC = 0.958，Accuracy = 96.9%
- **Top 5 特征**：税后持续利率（12.9%）、近四季持续 EPS（7.7%）、净利润/总资产（7.4%）、净值/资产（4.1%）、借款依赖度（4.1%）

### 3.2.3 专利影响力网络（PageRank）

以专利为节点、引用关系为有向边构建引用图谱，使用 NetworkX 的 PageRank 算法（阻尼系数 alpha=0.85）迭代计算每件专利的结构性影响力得分，再与引用次数、同族规模、国际布局、诉讼记录按 30% / 25% / 20% / 15% / 10% 的权重合成为专利质量分。该分数直接作为估值模型的输入特征之一，并单独在前端以网络图形式可视化呈现。

### 3.2.4 里程碑授信引擎

授信额度计算公式为：

> **最终授信 = AI 估值 × 30% × 里程碑进度系数 × (1 − 风险评分 × 0.5)**

其中里程碑进度系数由当前所处阶段与节点完成度共同决定。前端拖动进度滑块时，状态流转与额度同步重算，实现实时联动。

## 3.3 工程实现要点

- **优雅降级**：模型文件缺失或推理失败时自动回退规则公式，并在结果中标注估值来源（ML 模型 / 规则回退），保证服务可用性不因模型异常中断。
- **实时联动**：里程碑进度、企业切换、要素调整均触发全量指标重算并即时刷新。
- **可追溯性**：所有估值与风险结果标注产出来源，便于风控复核与监管审计。
- **可视化与响应式**：ECharts 深色主题深度适配，7 个业务组件、6 类图表形态，支持 1024px 与 640px 断点自适应。
- **链路完整性**：13 个 REST 端点覆盖企业、估值、团队、专利、里程碑、授信、风控全链路，形成端到端闭环。

## 3.4 开发与部署

前端使用 Vite 构建，后端基于 FastAPI 提供 OpenAPI 文档，模型以 joblib 序列化加载。开发环境使用 SQLite 单文件数据库，生产环境切换 MySQL；Redis 作为可选缓存，降级时不影响主流程。整套系统可容器化部署，支持私有化交付以满足银行数据不出域的要求。

# 四、市场分析

## 4.1 目标市场与客户定位

平台的目标客户为三类机构：**商业银行**（尤其是科技金融专营机构，作为系统采购与使用方）、**创业投资与 AIC 机构**（作为估值与风险参考工具的使用方）、**保险机构**（作为中试类保险产品的定价参考使用方）。服务的最终对象是半导体、商业航天、生物医药、高端装备、新材料、人工智能六大赛道的硬科技企业。

## 4.2 政策分析

政策环境对本项目高度有利，具体体现在三个层面：

**一是战略定位明确**。科技金融位列金融"五篇大文章"之首，"十五五"规划强调加快高水平科技自立自强，2025 年底中央经济工作会议明确"创新科技金融服务"。

**二是制度通道已打开**。金融监管总局明确指导商业银行开展知识产权质押融资内部评估试点，允许运用内部模型确定知识产权价值；《专利评估指引》国家标准发布实施，为模型输出提供了对标口径。这意味着本项目的技术路线不是监管灰色地带，而是政策明确鼓励的方向。

**三是试点基础具备**。8 省市知识产权金融生态综合试点围绕登记、评估、处置、补偿四大环节系统破壁，13 个省份、124 个地市出台风险补偿政策，试点已明确"评估试点效果、梳理创新举措、印发典型案例、研究扩大试点范围"，扩大可期。

# 五、营销策略

## 5.1 产品策略

采取"**核心模块 + 场景套件**"的产品结构。核心模块为企业画像引擎（估值 + 风险双模型）、专利影响力网络、里程碑授信引擎三大件，作为标准产品交付；场景套件针对不同赛道做差异化配置——半导体赛道强化"流片成功"节点与知识产权质押组合，生物医药赛道强化"临床 II 期"节点与中试保险衔接，高端装备与新材料赛道强化"量产爬坡"节点与供应链票据、订单融资衔接。

产品形态上提供三种交付方式：**SaaS 订阅**（面向中小银行与创投机构，轻量化接入）、**私有化部署**（面向大型银行，数据不出域）、**API 服务**（面向已有信贷系统的增量集成）。

## 5.2 价格策略

采用"**基础服务费 + 增量成效费**"的复合定价，降低机构初次采用门槛：

- **基础服务费**：按部署方式与接入企业数量收取年度许可费，私有化部署高于 SaaS 订阅。
- **增量成效费**：对通过本平台促成的新增授信，按金额收取一定比例的技术服务费，使平台收益与客户成效绑定。
- **试点期优惠**：对首批试点合作机构给予首年显著折扣或免费试点，以换取真实数据回测机会与标杆案例。

对学生团队创业项目而言，初期以"低门槛进入 + 案例积累"为优先目标，而非短期收益最大化。

## 5.3 推广策略

**渠道一：政策试点地区切入**。优先对接深圳、浙江、江苏、四川等知识产权金融生态综合试点省市的科技金融专营机构，借政策东风降低推广阻力。

**渠道二：赛事与生态背书**。依托"工行杯"等金融科技赛事的曝光，争取行业媒体与监管部门关注；积极参与监管组织的典型案例征集。

**渠道三：产业园区与孵化器合作**。与高新技术产业园区、硬科技孵化器、中试平台合作，从企业端形成需求拉动，反向推动机构端采购。

**渠道四：学术与行业会议**。在金融科技、科技金融相关学术会议与行业论坛发布技术报告，建立专业认知度。

## 5.4 服务策略

建立"**系统 + 专家 + 持续迭代**"的三层服务体系：

- **系统层**：提供 7×24 在线服务与可视化操作界面，模型异常自动降级不中断。
- **专家层**：配置"懂技术的金融人 + 懂数据的系统"双轮服务模式——平台输出量化结论，行业专家做人工复核与判断，避免纯黑箱决策。
- **迭代层**：按季度更新模型与专利图谱数据；为每家机构维护专属的模型反馈闭环，用其真实业务数据持续优化（在授权与合规前提下）。
- **培训层**：为银行客户经理与风控人员提供模型原理与结果解读培训，降低使用门槛与组织阻力。
